# `@carrental/mobile` — Car Rental customer app (React Native / Expo)

The customer-facing mobile counterpart to `apps/site`: browse the fleet, search availability,
book, manage trips, and manage the account — as a native iOS/Android app instead of a web page.

## Stack

- **Expo SDK 51** (React Native 0.74, New Architecture on) + **expo-router** (file-based routing,
  `src/app/`) — the same mental model as `apps/site`'s `app/[locale]/` tree.
- **TanStack Query** for all server state; **Zustand** only for the small local trip-search draft.
- **Hand-rolled theme system** (`src/lib/theme`), not NativeWind — driven by the real
  `@carrental/theme` brand tokens (`GET /meta/branding`), resolved to RN colors. No literal
  colors in components; see `src/lib/theme/theme-provider.tsx`.
- **`@stripe/stripe-react-native`** for payments, mirroring `apps/site`'s deferred-PaymentMethod
  checkout pattern.
- **`@carrental/contracts`, `@carrental/theme`, `@carrental/i18n`** are imported directly (they're
  framework-agnostic). `@carrental/client`'s `ApiError` and `createQueryClient` are reused too —
  its `apiFetch`/token-store/React hooks are browser-only (hard-wired to `document.cookie` /
  `localStorage`), so this app has its own RN equivalents in `src/lib/api/` that talk to the
  *same* endpoints, the *same* contracts, and the *same* session model (see the doc comments in
  `src/lib/api/api-fetch.ts` and `src/lib/auth/auth-provider.tsx` for exactly what differs and
  why). Product copy reuses the shared `@carrental/i18n` catalogue (`site.*`, `checkout.*`,
  `trips.*`, `auth.*`, …) everywhere it applies; `src/lib/i18n/mobile-resources.ts` adds only the
  handful of strings that are genuinely mobile-only (RTL relaunch, push priming, biometric unlock,
  onboarding).

## Running it

From the repo root:

```bash
pnpm build:packages        # builds @carrental/{theme,contracts,i18n,client,ui} — required once
pnpm --filter @carrental/api dev   # or: pnpm dev:up, see the root README
cp apps/mobile/.env.example apps/mobile/.env   # then point EXPO_PUBLIC_API_URL at your API
pnpm --filter @carrental/mobile start
```

Then press `i` / `a` in the Expo CLI, or scan the QR code with **Expo Go** (for a quick check —
push notifications, Stripe's native SDK, and biometrics need a **development build** instead;
`npx expo prebuild` + `pnpm build:dev` via `eas.json`, or `expo run:ios` / `expo run:android`
locally).

On a physical device, `EXPO_PUBLIC_API_URL` in `.env` must be your machine's LAN IP
(`http://192.168.x.x:3001/api/v1`), not `localhost`.

## Publishing to Google Play

Store listing assets (icon, feature graphic, screenshots, promo video), the listing copy and a
step-by-step publishing guide live in [`google-play/`](./google-play/README.md).
`pnpm build:production` builds the Play `.aab`; `pnpm build:production:apk` builds a sideloadable
`.apk` from the same profile.

## Structure

```
src/app/          expo-router routes (file-based) — screens only, minimal logic
src/components/   ui/ (themed primitives), booking/, trips/, vehicle/, checkout/
src/lib/
  api/            RN apiFetch + token store + cookie-jar CSRF read + React Query hooks
  auth/           AuthProvider, step-up modal, biometric app-lock
  i18n/           I18nProvider (RN RTL handling) + mobile-only resource additions
  theme/          ThemeProvider (brand tokens -> RN colors) + design tokens (spacing/type scale)
  payments/       Stripe SDK gate
  notifications/  push registration + tap-to-deep-link
  trip/           persisted trip-search draft (Zustand)
```

## Known gaps / next steps

- **Push delivery**: the client registers for a push token and is ready to receive/route
  notifications, but `apps/api`'s notify module doesn't have a `POST /notifications/push-tokens`
  endpoint yet (it currently drives email/SMS only) — see the comment in
  `src/lib/notifications/push.ts`. The call is written against the endpoint that integration
  should land on; it no-ops safely until then.
- **App icons/splash** (`assets/*.png`) are placeholders generated by
  `scripts/gen-placeholder-assets.mjs` from the brand primary color — replace with real design
  assets before a store submission (keep the filenames; `app.config.ts` references them by path).
- **Camera-based licence capture**: `expo-image-picker`/`expo-camera` permissions are wired in
  `app.config.ts` for this, but the actual capture-and-attach UI in the driver form isn't built
  yet — driver licence fields are text/date entry only.
- No test suite yet (`pnpm test:unit` is a placeholder) — the web apps' Vitest conventions would
  need an RN-appropriate equivalent (`jest-expo`).
